## 二、其他 RDM

查的是有源码、公开说明，或本机界面的几家。工作台有两家：Redis Insight、Redisee。没有一家靠「回复像不像表」来决定画不画表。

| 产品                                     | 有没有工作台                                                                | 命令结果怎么显示                                                                                                                                                                                                           |
| ---------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Redis Insight**                        | 有。连接内一页，上 Monaco，下结果卡片。内置视图只有文本                     | 表 / JSON / 图 / 地图都是插件。插件用 `matchCommands` 认**命令文本**，不读回复类型。`default: true` 的视图打开时就选中，否则要人手动切                                                                                     |
| **Another RDM**                          | 无。只有 CLI：上面输出、下面单行输入                                        | 结果进只读编辑器，按类型格式化成文本。[#1277](https://github.com/qishibo/AnotherRedisDesktopManager/issues/1277) 想要「像 Insight 那样跑一整文件」，1.7.0 做成了执行命令文件，仍然不是结果表                               |
| **Tiny RDM**                             | 无。命令行模式                                                              | [`cli_service.go`](https://github.com/tiny-craft/tiny-rdm/blob/main/backend/services/cli_service.go) 把任意回复 `AnyToString` 后按行打进终端                                                                               |
| **Medis / Medis 2**                      | 无。官网叫 Command Query，就是带高亮和补全的命令框                          | 公开材料没写结果表。Medis 2 闭源，不能从源码确认                                                                                                                                                                           |
| **Redisee**                              | 有。连接内页签，和仪表盘、终端、发布/订阅并列。上为带行号的编辑器，下为结果 | 结果是标签，标题用命令文本（如 `get RedisME`），可关闭。主按钮是「执行当前行」，带下拉。结果区有刷新、复制、下载和耗时。字符串按原文显示，换行写成 `\x0A`。编辑器里键参数下方有 `KEY` 标记。界面上看不到「按回复形状画表」 |
| **RESP.app**（原 Redis Desktop Manager） | 无，项目已停                                                                | 控制台是终端。网上「结果自动变表格」没有对应源码，不当依据                                                                                                                                                                 |

### Insight 怎么判断「有没有表」

内置视图只有文本，见 [`constants.ts`](https://github.com/RedisInsight/RedisInsight/blob/main/redisinsight/ui/src/pages/workbench/constants.ts) 的 `WBQueryType`：`Text` 和 `Plugin`。`getViewTypeOptions` 只放 `default__Text`。

插件清单在各自 `package.json` 的 `visualizations[].matchCommands`。匹配函数在 [`utils/plugins.ts`](https://github.com/RedisInsight/RedisInsight/blob/main/redisinsight/ui/src/utils/plugins.ts) 的 `getVisualizationsByCommand`：

- 把 `matchCommands` 里的一项编成「从行首开始，`*` 只匹配一段不含空白的字符，后面必须是空白或结尾」。`CLIENT LIST` 能对上，`FT.SEARCH` 能对上，`HGETALL` 对不上。
- 文档写支持正则，实现里星号是通配，不是把整段当正则。
- 地理插件另加 `matchQuery.anyRegex` / `noneRegex`，仍是在**命令文本**上找 `WITHCOORD` 之类，回复不参与。
- 命中之后，插件自己解析那种回复。`CLIENT LIST` 按行拆 `key=value` 再取第一行的键当列名。`FT.SEARCH` 由 redisearch 插件按它自己的回复布局画表。没有「数组就画表」的公共函数。

当前主分支上，会出表格（或图表）的命令是：

| 插件            | 视图               | 命令                                                                          | 默认打开             |
| --------------- | ------------------ | ----------------------------------------------------------------------------- | -------------------- |
| redisearch      | Table              | `FT.INFO`、`FT.SEARCH`、`FT.AGGREGATE`                                        | 是                   |
| redisearch      | Table              | `FT.PROFILE`                                                                  | 否                   |
| clients-list    | Table              | `CLIENT LIST`                                                                 | 是                   |
| clients-list    | JSON               | `JSON.GET`、`JSON.MGET`                                                       | 是                   |
| clients-list    | JSON               | `GET`                                                                         | 否，要手动切         |
| redistimeseries | Chart              | `TS.RANGE`、`TS.REVRANGE`、`TS.MRANGE`、`TS.MREVRANGE`                        | 是                   |
| redisgraph      | Graph              | `GRAPH.QUERY`、`GRAPH.RO_QUERY`                                               | 是                   |
| ri-explain      | 可视化             | `FT.EXPLAIN`、`FT.EXPLAINCLI`、`FT.PROFILE`、`GRAPH.EXPLAIN`、`GRAPH.PROFILE` | 是                   |
| geodata         | 地图 / 热力 / 详情 | `GEOSEARCH`、`GEORADIUS*` 等，且命令里要有 `WITHCOORD` 或地理过滤             | 地图默认，热力不默认 |

`HGETALL`、`SMEMBERS`、`LRANGE`、`XRANGE`、`ZRANGE`、`INFO`、`KEYS` 都不在里面，工作台里就是文本。这些命令的表在键浏览器里，不在工作台。

对我们的含义：表跟着 Insight 的默认表走，不跟着「回复是数组 / 键值交替」走。`HGETALL` 这类值页已经是表，工作台不认。插件机制本身不做。图和 JSON 插件视图也不做，文本格式里已有 JSON。

## 三、终端现在缺什么

终端是 [`vue-web-terminal`](../../docs/zh/guide/usage/terminal.md) 的单行会话：回车即执行，历史靠 ↑ / ↓。多行只出现在粘贴弹框里，而且要人先选「一条」还是「每行一条」。

输出只有格式化后的字符串。`execute_command` 返回 `String`，经 `redis_value_to_cli_display` 变成 TTY / Raw / JSON / CSV。默认已是 Raw。没有行、没有列，不能排序、不能点一个键跳到值页、也不能按列导出。

所以：

- 一条 `EVAL`、一段 `FT.CREATE`、一份带换行的 `JSON.SET`，在终端里要么挤成一行，要么靠粘贴弹框碰运气。
- `HGETALL`、`FT.SEARCH`、`XRANGE`、`CLIENT LIST` 这类本来就是行，在终端里是绿字文本。搜索页把 `FT.SEARCH` 做成了表，其它命令没有。

工作台只解决这两件。单行 `GET`、临时看一眼，仍走终端。

## 四、两种场景

### 4.1 多行输入：成立，这是主因

Redis 没有 SQL 那种分号结尾，但有两类「多行」：

1. **一条命令跨多行**。参数在引号里换行：`EVAL` / `FUNCTION LOAD` 的脚本，`JSON.SET` 的文档，`FT.CREATE` 的长 schema。
2. **多条命令排在一起**。连续的 `GET` / `HGETALL` / `FT.SEARCH`，想一次跑完并各自留结果。

终端的粘贴弹框把这两类绑成一次二选一。工作台用一套拆分规则同时覆盖，编辑器里可以直接改，不必先粘贴。

拆分对齐 redis-cli 读脚本：引号外的换行结束一条命令，引号内的换行仍属同一条；空行跳过；整行以 `#` 开头的是注释。因此：

- `GET a` 换行 `GET b` 是两条。
- `SET k "hello` 换行 `world"` 是一条。
- `EVAL` 的脚本必须写在引号里。编辑器不发明 heredoc，避免和真正发到服务器的参数不一致。

执行都用同一套拆分。主按钮跟 DBeaver、DataGrip，不跟 SSMS，也不把 Redisee 按钮上的「执行当前行」当成唯一行为：

- 有选区：主按钮是「执行选区」，只跑选区。
- 没有选区：主按钮是「执行当前行」，跑光标所在的那一条。引号跨行时，光标在引号里也算这一整条。光标在空行或整行注释上时不发命令。
- 下拉里的「执行全部」：编辑器全文。

DBeaver 的 Ctrl+Enter、DataGrip 的执行语句都是这条规则：有选区跑选中的语句，否则跑光标所在的语句，整篇另走一个动作。SSMS 的 F5 是有选区跑选区、没选区跑整篇，脚本一长就容易把没看的后半段发出去。Redisee 主按钮写着「执行当前行」，下拉里有什么这张图没展开。

多条命令在同一条连接上排队，一条结束再发下一条。第一条报错就停。已经发出的成功结果留在各自的标签里，后面的命令不发。不默认「出错继续」。

订阅、阻塞、`MONITOR` 与终端同一份拒绝名单，不打到共享连接。`SELECT` 同样走终端那条同步切库，不把库切在会话外面。只读连接沿用 `isReadonlyCommand`。

### 4.2 表格结果：按命令名，不按回复形状

RESP 没有表头。Insight 也不看回复是不是数组，只认命令名（§二）。见到数组就画表，会把 `SCAN` 的游标和键列表捏成一张错表。`HGETALL` 即使很像两列，值页已经是表，工作台不必再认。

阶段 2 才出现「表」。在那之前结果只有文本。

- 默认视图是文本，格式与终端一致，默认 Raw。任何命令都有文本。
- 只有下表里的命令多一个「表」。命令名大小写不敏感，只看第一个词加固定子命令（`CLIENT LIST`），参数不影响。
- 未点名的命令没有「表」，也不提供「自动猜列」。

| 命令                                                                | 阶段 2               | 表从哪来                                                                                                                                                               |
| ------------------------------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLIENT LIST`                                                       | 做                   | 与 Insight 的 clients-list 相同：按行拆空格，再拆 `key=value`，列名取第一行的键。原文就能拆                                                                            |
| `FT.SEARCH`                                                         | 做                   | 按这条命令自己的回复布局解析。搜索页的 `searchQuery` 是用索引、查询串、`LIMIT`、是否带分数组出来的，接不住编辑器里的原文（`RETURN`、`DIALECT`、任意 `LIMIT` 都对不上） |
| `FT.AGGREGATE`                                                      | 做                   | Insight 默认就是表。另一套回复布局，单独解析                                                                                                                           |
| `FT.INFO`                                                           | 做                   | Insight 默认就是表。搜索页有索引详情，那是专用接口，工作台仍按这条命令的回复解析                                                                                       |
| `HGETALL`、`SMEMBERS`、`LRANGE`、`XRANGE`、`ZRANGE`、`INFO`、`KEYS` | 不做                 | Insight 工作台也是文本。结构化看走值页或信息页                                                                                                                         |
| `JSON.GET`、`GET`                                                   | 不做单独的 JSON 视图 | 文本格式里已有 JSON。Insight 对 `GET` 的 JSON 视图默认还是关的                                                                                                         |
| `TS.*`、`GRAPH.*`、`GEO*`、`FT.PROFILE`                             | 不做图               | Insight 用插件画图。`FT.PROFILE` 的表默认是关的                                                                                                                        |

表里的键名列可点，打开方式与搜索页相同：写入 `share.redisKey`，切到值页，`KEY_REFRESH`。非键的列只展示。

二进制和非法 UTF-8 不进表，该条结果停在文本，避免表格把字节显示成替换字符后再被复制出去。

## 五、首版界面

```text
┌ 工作台 ──────────────────────────────────────────────┐
│ [执行当前行 ▾]  节点（集群）  文本格式 Raw ▾          │
│ ┌ 编辑器 MeCode ───────────────────────────────────┐ │
│ │ FT.SEARCH idx "*" LIMIT 0 20                     │ │
│ └──────────────────────────────────────────────────┘ │
│ 执行结果  [get RedisME ×] [FT.SEARCH idx … 📌 ×]     │
│ ┌ 当前标签 ─────────────────────────── 文本 | 表 ─┐ │
│ │ 耗时、MeTable 或等宽文本                         │ │
│ └──────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

- 编辑器复用 `MeCode`（换行、行号、选区、已有右键）。不要把 vue-web-terminal 嵌进来再关掉回车执行。首版不做命令名、键名补全，也不做 Redisee 那种参数下方的 `KEY` 标记。
- 上下分栏可拖。一次执行里的每条命令各占一个结果标签，标题用命令摘要，横排，不上下堆。标签可关。
- 再次执行时只回收未固定标签。固定的留在原位，既不覆盖也不关闭：
  - 从左到右找出未固定标签，按这个顺序盖上这一轮的结果（标题和内容一起换）。
  - 这一轮条数更少：多出来的未固定标签关掉。更多：在末尾新开。
  - 一个未固定标签都没有（全固定，或已经关光）：这一轮全部新开在末尾。
  - 例：`[固定 A][未固定 B][未固定 C]`，这一轮只有 1 条 → `[固定 A][这条新结果]`，C 关掉。这一轮有 3 条、未固定只有 B → 盖掉 B，再在末尾新开两个，A 不动。
  - 反复执行同一条、又不固定：始终只有一个标签。固定后再执行：旧标签留着，末尾新开一个；新的未固定，再执行就盖掉这个新的。
- Redisee 这张图只有一个结果标签和「执行当前行」，看不到固定按钮。固定 / 复用按上面的规则做，不照着那张图猜它有没有图钉。
- 命令历史、带标题的草稿、集群节点下拉都在阶段 3。阶段 1 不广播，命令打在当前连接上。
- 页签放在终端旁边。极简模式仍只有值和终端。阶段 1 切走再回来，编辑器正文还在；关应用不留，持久化等到阶段 3 的草稿。
- 大结果：表最多渲染前 N 行（建议 1000），底栏写明截断。文本同样截断。不要为工作台再造分页协议；命令自己带 `LIMIT` / `COUNT`。阶段 1 还没有表，截断先用在文本上。

文本走现有 `executeCommand` + `outputMode`。阶段 2 的表不能从 TTY / Raw 文本反解析。`CLIENT LIST` 可以按行拆原文。`FT.SEARCH`、`FT.AGGREGATE`、`FT.INFO` 同一次执行要另拿结构化回复，再按各自的布局解析。

## 七、手测时看这几条

阶段 1：

1. 引号内换行的 `SET` / `EVAL` 只发一条；引号外换行的两条 `GET` 出两个结果标签，不上下排成两块。
2. 未固定时连着执行两次，还是一个标签，内容被盖掉。`[固定 A][未固定 B][未固定 C]` 再执行 1 条，变成 `[固定 A][这条新结果]`，C 关掉。
3. 有选区时主按钮跑选区。没有选区时跑光标所在命令，不跑其它行。空行不发命令。
4. 第一条写命令失败后，后面的命令不发。已经成功的留在各自的标签里。
5. 只读连接拒绝写命令，提示与终端一致。`SUBSCRIBE`、`BLPOP`、`MONITOR` 被拒绝。
6. 切走页签再回来，编辑器正文还在。关掉应用再打开，正文不在。
7. 阶段 1 没有「表」，也没有命令补全、键名补全、草稿和集群节点下拉。

阶段 2：

8. `CLIENT LIST`、`FT.SEARCH`、`FT.AGGREGATE`、`FT.INFO` 可以切表。`HGETALL`、`GET`、`INFO` 没有「表」。
9. `FT.SEARCH` 的表能点文档键进入值页。带 `RETURN` 的那条命令，列和回复一致，而不是搜索页那组固定参数。
10. 超长回复被截断，且界面写明没有全部显示。

阶段 3：

11. 草稿关掉应用再打开还在。终端历史不因此多出几条。
12. 集群不选节点时不广播；选了节点只打那一个。

## 八、阶段

### 阶段 1：能写、能跑

编辑器、三种执行、结果标签（含固定和回收）、文本格式、只读 / 订阅 / 阻塞 / `SELECT`。切走页签正文还在。结果只有文本。

### 阶段 2：对齐 Insight 的默认表

`CLIENT LIST`、`FT.SEARCH`、`FT.AGGREGATE`、`FT.INFO`。后三条按命令原文解析结构化回复，不走搜索页的 `searchQuery`。键列点开值页。

### 阶段 3：留着下次用

带标题的本地草稿（38 §3.17 的脚本列表）、命令历史、集群节点下拉（默认不广播）。`FUNCTION LIST` 查看后填进编辑器可以跟草稿一起做。补全和 `KEY` 标记仍在这之后。
